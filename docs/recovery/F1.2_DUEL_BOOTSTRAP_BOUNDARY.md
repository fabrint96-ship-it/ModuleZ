# F1.2 production Duel bootstrap boundary

## Summary

`DuelSceneRoot` and `DuelBootstrap` establish the scene-scoped production composition boundary for the preserved `Duel3DRuntimeBuilder`. Neither class is a singleton or persistent object, and neither owns navigation, save, progression, settings, platform integration, rules, AI, or input.

## Architecture

```text
Duel scene
  -> DuelSceneRoot (Uninitialized / Initializing / Ready / Failed)
     -> DuelBootstrap
        -> owned child Duel3D_Runtime
           -> existing Duel3DRuntimeBuilder
```

`DuelSceneRoot` keeps explicit references to the runtime GameObject and builder. `DuelBootstrap` reports creation success/failure to the root. No global lookup is used to recover those references.

## Legacy behavior preserved

- `Duel3DRuntimeBuilder` remains the Duel runtime builder and is not modified.
- Duel rules, board, pieces, AI, UI, audio, results, save, progression, input, and return navigation are unchanged.
- Direct debug scene entry can still inject the configured debug rival and perform its legacy name cleanup.

## Production boundary introduced

During the transitional scene arrangement, the serialized `Duel3DDebugBootstrap` is a DEBUG -> PRODUCTION adapter: it creates `DuelSceneRoot` plus `DuelBootstrap`, which own and create the runtime. When a legitimate `ModuleZDuelSessionState` is active, the adapter does not inject a debug rival, reset result flags, or run cleanup-by-name.

`Duel.unity` is intentionally unchanged. A later focused scene-migration slice can serialize the production root/bootstrap and remove the debug adapter from the production scene after owner validation.

## Transitional state dependencies

`DuelContext` is deliberately not introduced. `DuelBootstrap` validates the existing startup state without mutating it:

1. Active `ModuleZDuelSessionState.RivalId` is the normal production input.
2. `ModuleZGameState.PendingDuelRival` remains the legacy fallback for direct scene/debug compatibility.

These are pre-existing sources consumed by `Duel3DRuntimeBuilder`; the boundary adds no new mutable global state or independent source of truth.

## Debug separation status

The production classes have no dependency on `Duel3DDebugBootstrap`. The remaining scene-level adapter is explicit transitional debt. Debug-only rival injection and cleanup are restricted to entry without an active production session.

The legacy cleanup list was inspected. Its eight names occur nowhere else in current ModuleZ source/scenes/prefabs. Cleanup-by-name is therefore absent from the production boundary and retained only for direct debug compatibility.

## Known limitations

- The production scene still serializes `Duel3DDebugBootstrap` as a transitional adapter.
- `Duel3DRuntimeBuilder` still consumes and synchronizes legacy static state.
- `DuelContext` and `DuelResult` remain unimplemented.
