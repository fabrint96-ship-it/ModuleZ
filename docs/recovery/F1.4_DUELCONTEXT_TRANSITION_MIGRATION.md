# F1.4 — DuelContext Transition Migration

Slice: `S1.4-02`

Status: implementation complete; owner runtime validation required

## 1. Scope

This slice implements the production OpenWorld → Duel intent boundary: immutable context, one-way Legacy projection, existing delayed navigation, one accepted startup context, and explicit runtime configuration. It does not migrate Duel results or redesign gameplay, progression, persistence, UI, audio, AI, rules, scenes, or navigation.

## 2. Baseline

Base: `d8abbb677af5a0c29aa15c79de5995ea27dcbec1`

This baseline merges the S1.4-01 repository characterization in `F1.4_DUEL_TRANSITION_CHARACTERIZATION.md`.

## 3. Contract placement decision

`DuelContext` and `DuelTransitionBridge` are placed in `Assets/ModuleZ/Game/DuelTransition` under namespace `ModuleZ.Game.DuelTransition`. This neutral gameplay location is consumable by the OpenWorld producer and Duel startup without adding a Core-to-OpenWorld dependency.

The contract temporarily references the existing `ModuleZ.OpenWorld.Encounters.ModuleZRivalId`. The enum is not moved, renamed, duplicated, or reserialized. Neutral rival-type placement remains later architectural debt.

## 4. DuelContext definition

`DuelContext` is a `readonly struct` with construction-only properties:

| Field | Type | Purpose |
| --- | --- | --- |
| `RivalId` | `ModuleZRivalId` | Duel match/profile/presentation and result association |
| `IsRematch` | `bool` | Existing rematch policy, counters, and messages |
| `ReturnPosition` | `Vector3` | Existing OpenWorld return spawn |

It contains no GameObject, service, UI, result, progression, statistics, message, scene-name, or mutable global state.

## 5. DuelTransitionBridge responsibility

`DuelTransitionBridge` is a stateless operation class. `Begin(context)` validates the rival and projects the context into required Legacy compatibility fields. `CompleteAfterDelay(context)` preserves pre-load pause clearing and requests the existing `ModuleZSceneController.LoadDuel()`.

The bridge does not store a current context, own results, save, change progression/achievements, implement gameplay, or introduce a singleton/DDOL/event bus/service locator.

## 6. Legacy projection map

| Contract/source | Legacy projection | Timing |
| --- | --- | --- |
| `RivalId` | `PendingDuelRival` | interaction acceptance |
| complete context | `ModuleZDuelSessionState.StartDuel(...)` | interaction acceptance |
| `RivalId` | `CurrentDuelRival` | interaction acceptance; repeated from accepted context at Duel runtime initialization |
| `IsRematch` | `CurrentDuelIsRematch` | interaction acceptance; repeated from accepted context at Duel runtime initialization |
| `ReturnPosition` | `OpenWorldReturnPosition` | interaction acceptance; repeated from accepted context at Duel runtime initialization |
| transition marker | `ReturningFromDuel = true` | interaction acceptance, preserving misleading Legacy semantics |
| entry reset | four Legacy result flags set `false` | interaction acceptance |
| navigation preparation | `IsPaused = false` | after existing 1.5-second delay, immediately before load |

The projections remain required by unchanged result/return consumers. They are compatibility outputs, not contract authority.

## 7. Timing and reset consolidation

The existing interaction message/animation occurs before context construction. Successful bridge projection occurs at the same interaction stage as the former direct writes. `DuelStarterInteractable` retains `Invoke(nameof(StartDuel), 1.5f)`, so transition delay is unchanged.

The four outcome flags were previously reset during interaction and again immediately before scene loading. They are now reset once by `Begin`. Repository evidence found no writer during the delay, so the duplicate reset was consolidated without changing normal observable state. `IsPaused = false` remains immediately before navigation.

The accepted context is held only in the initiating `DuelStarterInteractable` instance during the delay; this is scene-local pending operation state, not a global context holder.

## 8. DuelBootstrap accepted-context flow

`DuelBootstrap.TryResolveAcceptedContext` now constructs exactly one context:

1. Normal production: active `ModuleZDuelSessionState` → `DuelContext`.
2. Direct-scene fallback: pending rival plus current rematch/return Legacy values → `DuelContext`.

The rival is validated once. The accepted value is passed to the newly added `Duel3DRuntimeBuilder` immediately through `Initialize`, before Unity invokes its `Start` method.

## 9. Duel3DRuntimeBuilder migration

`Duel3DRuntimeBuilder.Initialize(context)` accepts one context and rejects repeat configuration. `Start` refuses to build without configuration. `BuildDuel3D` projects only the accepted context into current rival/rematch/return compatibility fields before existing configuration, profile, visual, audio, dialogue, AI, board, and UI construction.

The builder no longer reads the session and then unconditionally overwrites its rival from `PendingDuelRival`. It does not independently resolve competing stores.

## 10. Direct-scene fallback

When no active session exists, `DuelBootstrap` preserves the former valid direct-scene/default behavior by constructing a context from:

- `ModuleZGameState.PendingDuelRival`;
- `ModuleZGameState.CurrentDuelIsRematch`;
- `ModuleZGameState.OpenWorldReturnPosition`.

Static defaults therefore still permit Madrid direct entry. This path converges on the same explicit builder initialization and is transitional, not normal production authority.

## 11. Remaining Legacy compatibility

`ModuleZDuelSessionState` still transports data across the scene load. `ModuleZGameState` fields remain for unchanged runtime/result/return consumers. `ReturningFromDuel` remains set before entering Duel. Result flags remain boolean compatibility outputs. No Legacy field or save schema is removed.

## 12. Split-authority resolution

For an active production session:

```text
bridge context RivalId
  = session RivalId
  = DuelBootstrap accepted RivalId
  = Duel3DRuntimeBuilder accepted RivalId
  = CurrentDuelRival projection
  = runtime config/profile/presentation rival
```

`PendingDuelRival` remains a compatibility projection but is not read by normal runtime startup and cannot override the accepted context.
