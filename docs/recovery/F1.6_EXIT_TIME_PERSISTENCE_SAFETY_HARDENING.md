## Exit-time cause and isolation boundary

Boot's `ModuleZ_Runtime` is a `DontDestroyOnLoad` owner of `ModuleZAutoSaveController`. Its `OnApplicationQuit` calls `ModuleZSaveManager.SaveGame` after PlayMode teardown. Clearing the per-test override before Unity exits formerly exposed `Application.persistentDataPath`. `ModuleZPersistencePaths` now captures an explicit process root once. A cleared per-test override falls back to that process root until process exit. Interactive production without an override retains `Application.persistentDataPath` and the autosave callback is unchanged.

The validation wrapper sets `MODULEZ_PERSISTENCE_ROOT` and `MODULEZ_VALIDATION_ISOLATED=1` before launching Unity, retains them until the tracked process exits, then fingerprints the real save and settings after exit. A mismatch fails validation independently of Unity's exit code or test XML. `ModuleZPersistencePaths` rejects an invalid validation marker, a whitespace root, and a missing root in batchmode or a marked validation process. Windows may represent an explicitly empty environment value as absent; batchmode and the validation marker still make that state fail closed. This also guards a batchmode relaunch that loses its inherited environment. The wrapper still requires a supported Windows Unity process launch; all validation should use it rather than invoking Unity directly.

## Path alias guard

Before launch, the wrapper checks the isolated root and real-profile path chains for existing `ReparsePoint` ancestors. It checks before creating the per-process directory and again afterward. It rejects lexical overlap as well. This conservatively rejects junctions, directory symlinks and mount-point reparse paths rather than attempting to resolve them and guess whether they are safe.

Read-only inspection found no reparse ancestors on the current output or profile chains. Temporary-directory checks accepted separate roots, rejected an overlapping root, and rejected a junction ancestor. Symbolic-link creation required administrator privilege and could not be exercised here; the same `ReparsePoint` attribute check covers that type. No test path pointed to the production profile.

## Relaunch and suite separation

The wrapper sets process environment before `Start-Process`. A Unity child/relaunch normally inherits that environment; the process root is immutable once its type initializes. The wrapper identifies replacements by the run's log-file command-line token and rejects a detected replacement missing `-batchmode`. If a replacement loses the environment while retaining `-batchmode`, persistence resolution throws rather than using the real profile. The external fingerprint check runs after the tracked process exits.

`shutdown` is a separate one-test PlayMode stage and requires an isolated exit-time save. Ordinary `playmode`, `tests` and `all` exclude `Shutdown` but include the existing `Persistence` fixture. The smoke fixture and `smoke` wrapper stage are not in this branch, so shutdown evidence cannot be mistaken for canonical smoke evidence.

## Validation and limits

PowerShell syntax, static architecture checks and temporary path-guard checks passed in the original working checkout. This isolated branch independently passed the 32 static checks, Unity compile/import (exit 0), the dedicated shutdown regression (1/1 passed, exit 0), and the persistence suite (5/5 passed, exit 0). The shutdown process wrote a nonempty `modulez_save.json` beneath its unique ignored `artifacts/validation/process-data/` root. The wrapper's external post-exit guard and a separate fingerprint comparison found both real profile files unchanged after all three Unity runs. The shutdown XML contains only `PERSIST_EXIT_001`; the fixture did not load Boot, OpenWorld or Duel. No canonical smoke or gameplay-scene validation was run. `git diff --check` passed before commit.

The path checks are not a defense against an adversary replacing directories between validation and use. The replacement scan has a bounded discovery window, and a later or unrelated process that discards both the inherited environment and `-batchmode` is outside the wrapper's guarantee. Per-test `SetRootOverride` accepts an explicit path and is not independently reparse-guarded; validation must use the guarded process root and never point a test override at the real profile. The current Windows profile derivation follows the project's Company/Product settings and must be revisited for another OS. The separately preserved canonical smoke remains disabled pending its own validation.
