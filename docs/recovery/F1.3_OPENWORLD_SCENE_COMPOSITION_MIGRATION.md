## Runtime camera ownership

Production startup remains:

```text
OpenWorld_Runtime.OpenWorldRuntimeBuilder
  -> create runtime Player
  -> OpenWorldGameplayCameraBuilder.Create(Player)
  -> runtime Main Camera
     ├── Camera
     ├── AudioListener
     └── ModuleZThirdPersonCamera
  -> OpenWorldSceneRoot.Initialize(explicit references)
  -> Ready
```

The gameplay Camera remains dynamically created because it requires the runtime Player target. Its name, `MainCamera` tag, FOV 50, Skybox clear flags, controller, target, initial offset `(0, 3.2, -4.5)`, and look target remain unchanged from S1.3-01.

Expected normal runtime counts are one gameplay Camera, one MainCamera-tagged GameObject, one active AudioListener, one `ModuleZThirdPersonCamera`, and one `OpenWorldSceneRoot`. These expectations require owner Play Mode verification and are not claimed as observed by static validation.

## AudioListener ownership

The only remaining production OpenWorld listener creation path is `OpenWorldGameplayCameraBuilder`. It creates the AudioListener on the same GameObject as the gameplay Camera and controller. `OpenWorldSceneRoot` validates that shared ownership before reaching `Ready`.

No listener manager, arbitration, disabling, destruction, global owner, lookup, or broader audio-system change is introduced.

## Scene-root fallback decision

The `OpenWorldRuntimeBuilder.Start()` resolve-before-add fallback is retained unchanged:

1. `GetComponent<OpenWorldSceneRoot>()` resolves the serialized production component.
2. `AddComponent<OpenWorldSceneRoot>()` runs only when the required component is absent.

This is defensive transitional compatibility for direct/debug content using the builder, not a parallel production composition path. The enabled production scene supplies the component, so the add branch is not expected during normal startup. No global lookup is involved.
