## Stage and safety contract

`Invoke-ModuleZValidation.ps1` exposes `static`, `compile`, `editmode`, `playmode`, `tests`, `persistence`, `smoke`, `shutdown`, and `all`. The source switch currently maps:

| Stage | Selection / work |
|---|---|
| `static` | Existing static validator only (the wrapper still resolves Unity first; CI invokes validator directly) |
| `compile` | Unity import/compile only |
| `editmode` | EditMode assembly |
| `playmode` | PlayMode `!Smoke;!Shutdown`, including `Persistence` and command/runtime tests |
| `tests` | EditMode, then ordinary PlayMode |
| `persistence` | PlayMode `Persistence` only |
| `shutdown` | PlayMode `Shutdown` only; requires isolated exit-time save |
| `smoke -EnableSmoke` | PlayMode `Smoke` only; wrapper sets the temporary opt-in marker |
| `all` | Static, compile, EditMode, ordinary PlayMode; excludes smoke and shutdown |

The wrapper rejects `smoke` without `-EnableSmoke` and rejects `-EnableSmoke` with other stages before Unity resolution. The smoke fixture itself ignores execution without `MODULEZ_CANONICAL_SMOKE_OPT_IN=1` before loading Boot. `Invoke-UnityProcess` establishes a unique process storage root, checks lexical overlap and reparse-point ancestors, follows the Unity process/replacement, and compares both real-profile fingerprints **after Unity exits**, irrespective of XML. These are reviewed source guarantees, not a new process execution in this slice. A direct Test Runner invocation with a manually supplied opt-in marker is outside wrapper protection and should not be used for smoke.
