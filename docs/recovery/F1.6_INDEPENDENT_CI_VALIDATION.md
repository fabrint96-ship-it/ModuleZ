# F1.6-06 — Independent static CI foundation

## Scope and baseline

This slice adds a GitHub Actions validation job from `develop` baseline
`e4b956874f053c04115afd2c765bd238f155e283`. It adds no production,
scene, package, ProjectSettings, test, or persistence change. REC-007 remains
in progress; independent CI is one layer of its eventual closure.

## Execution contract

`.github/workflows/modulez-static-validation.yml` runs for pull requests
targeting `develop` and supports `workflow_dispatch` after the workflow is
available on the default branch. The job uses a GitHub-hosted `windows-latest`
runner, PowerShell 7 (`pwsh`), a ten-minute timeout, and `contents: read`
token permission. It does not request repository secrets or a Unity license.

The job checks out the repository, parses both checked-in validation scripts
with the PowerShell language parser, and proves two wrapper guards reject:
`smoke` without `-EnableSmoke` and `static -EnableSmoke`. Both negative calls
receive a verified nonexistent Unity executable path; they must reject with
their specific guard messages before Unity resolution. They cannot launch
Unity even if a guard regresses. The job then runs the existing static
validator directly rather than duplicating its 32 rules in workflow YAML.
The top-level wrapper currently resolves a local Unity executable before
dispatching even its `static` stage, so it is not the Unity-independent CI
entry point.

The guard probes are expected to return nonzero. GitHub's `pwsh` shell also
propagates the last native exit code at step completion, so the workflow clears
`LASTEXITCODE` only after verifying both required failures and their messages.
An unexpected result throws before that clearing and still fails the job.

## Failure and artifacts

A PowerShell parse error, missing/incorrect guard rejection, nonzero static
validator exit, missing result JSON, or non-PASS JSON overall status fails the
validation job. The validator writes `artifacts/validation/static-results.json`
and `static.log`; the workflow attempts to upload both with
`actions/upload-artifact@v4` even if validation fails. If failure occurs before
those files exist, artifact upload warns rather than masking the original
failure. Generated artifacts remain ignored by Git.

The workflow does not invoke `Invoke-ModuleZValidation.ps1 static` because
that wrapper still performs Unity discovery first. It never invokes compile,
EditMode, PlayMode, persistence, shutdown, smoke, or gameplay scenes. It does
not read or write player save/settings profiles.

## Local validation and limits

Locally, the workflow parsed as one YAML document with the expected `on`,
`permissions`, and `jobs` keys. Its two inline PowerShell validation steps
were executed with CI-style workspace/temp variables: both negative guard
probes passed without Unity, and all 32 static checks passed (27 exact,
5 heuristic; no warnings or failures). PowerShell syntax and
`git diff --check` also passed. The GitHub-hosted execution result must be
judged from the PR check after push; local validation cannot be reported as
an Actions PASS. This job checks
source/scene architecture only, not Unity import/compile, runtime behavior,
serialization through the Editor, gameplay, performance, or persistence
isolation under Unity. Unity-capable CI and branch-protection configuration
remain separate future decisions. A passing job does not replace the guarded
local runtime-health tests, controlled canonical smoke, or owner acceptance.
