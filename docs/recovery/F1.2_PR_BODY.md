## Summary

Introduces the F1.2 production Duel startup boundary while preserving the existing Duel3D runtime implementation and gameplay behavior.

## Architecture

- Adds scene-scoped `DuelSceneRoot` lifecycle ownership: `Uninitialized`, `Initializing`, `Ready`, `Failed`.
- Adds `DuelBootstrap` as the production runtime composition entry.
- The root owns explicit references to the created `Duel3D_Runtime` GameObject and existing `Duel3DRuntimeBuilder`.
- No singleton, DDOL object, or mutable global state is added.

## Legacy behavior preserved

`Duel3DRuntimeBuilder`, Duel rules, board, pieces, AI, UI, audio, results, save, progression, input, and navigation are unchanged. Direct debug scene entry retains debug rival injection and legacy cleanup.

## Production boundary introduced

The existing serialized debug bootstrap temporarily acts as a DEBUG -> PRODUCTION adapter. With an active production session it does not inject debug state or run cleanup-by-name; it creates the scene root/bootstrap boundary, which creates the owned existing runtime.

## Transitional state dependencies

Normal entry validates `ModuleZDuelSessionState.RivalId`. The existing `ModuleZGameState.PendingDuelRival` remains a direct scene/debug fallback until the future `DuelContext` migration. No third source of truth is added.

## Debug separation status

Production classes have no dependency on `Duel3DDebugBootstrap`. `Duel.unity` still serializes the debug component as a transitional adapter; later scene migration remains required. Production entry skips debug rival/result injection and name cleanup.
