# F1.4 — DuelResult Transition Migration

Slice: `S1.4-03`

Status: implementation complete; owner runtime validation required

## 1. Scope

This slice migrates Duel completion to an explicit result fact and one-way compatibility bridge. It preserves the existing result manager as the owner of progression, statistics, messages, saving, session cleanup, delayed navigation, and Legacy result projections. It does not remove Legacy state or change Duel rules, Draw product semantics, persistence, progression, achievements, UI, scenes, or OpenWorld composition.

## 2. Baseline

Base: `1a1a548a05a3299274712e16684ffc2175b09666`

The baseline contains the merged F1.4 transition characterization and DuelContext migration.

## 3. Current result flow before migration

Before this slice, `Duel3DRuntimeBuilder.HandleMatchFinished` called separate `WinDuel` or `LoseDuel` operations. Draw called `LoseDuel`. `DuelPauseMenuController` called `AbandonDuel` through the existing scene-local result-manager singleton.

Each result operation independently resolved rival identity from active session state or `CurrentDuelRival`. Rematch policy and defeat/abandon message identity were independently read from `ModuleZGameState`. Each branch then wrote flags/statistics/messages, optionally wrote progression, saved, cleared the session, and scheduled return.

## 4. DuelOutcome

`ModuleZ.Game.DuelTransition.DuelOutcome` contains exactly:

- `Victory`
- `Defeat`
- `Abandoned`

Draw is intentionally not a contract outcome.

## 5. DuelResult

`DuelResult` is a readonly struct containing exactly:

| Field | Type |
| --- | --- |
| `Outcome` | `DuelOutcome` |
| `RivalId` | `ModuleZRivalId` |

It contains no setters, Unity object references, UI strings, progression/statistics facts, save result, navigation data, return position, rematch state, or Legacy flags.

## 6. Contract placement

`DuelOutcome`, `DuelResult`, and `DuelResultBridge` reside in `Assets/ModuleZ/Game/DuelTransition` under `ModuleZ.Game.DuelTransition`, beside `DuelContext` and the entry bridge. The existing `ModuleZRivalId` remains unmoved and is a documented transitional dependency.

## 7. Accepted-context authority

The `DuelContext` accepted by `DuelBootstrap` remains stored only on the owned `Duel3DRuntimeBuilder`. During composition the builder explicitly initializes the scene-local `Duel3DResultManager` with that same context. Neither match completion nor abandon reconstructs context from Legacy globals.

## 8. Match-result mapping

`Duel3DRuntimeBuilder.HandleMatchFinished` maps once:

| Runtime result | Contract outcome |
| --- | --- |
| `PlayerWin` | `Victory` |
| `OpponentWin` | `Defeat` |
| `Draw` | `Defeat` |

The builder creates `DuelResult(outcome, acceptedContext.RivalId)` and submits it to its initialized result manager.

## 9. Abandon mapping

The unchanged pause-menu entry invokes `Duel3DResultManager.AbandonDuel`. That thin adapter constructs `DuelResult(Abandoned, acceptedContext.RivalId)` from the manager's explicitly initialized runtime-local context, then follows the same bridge and compatibility routine as match completion.

## 10. DuelResultBridge responsibility

The bridge is stateless. `Complete` validates the outcome, rival enum value, exact context/result rival identity, and availability of the focused compatibility processor. Only after validation does it invoke that processor. It does not store results or implement progression, statistics, saving, messages, UI, session ownership, or navigation.

## 11. Result-manager migration

`Duel3DResultManager` now has one `Complete(DuelResult)` entry for runtime results and one thin abandon adapter. It holds the accepted context as instance state, invokes the bridge, and applies the existing specialized compatibility side effects through one outcome switch. The former separate rival-resolution paths are removed.

## 12. Legacy flag projection

| Outcome | Completed | Cancelled | Lost | Abandoned |
| --- | --- | --- | --- | --- |
| Victory | `true` | `false` | `false` | `false` |
| Defeat | `true` | `false` | `true` | `false` |
| Abandoned | `true` | `false` | `false` | `true` |

These remain compatibility destinations. `CurrentDuelIsRematch` is reset to false after rematch policy and message selection, as before.

## 13. Victory side effects

Victory increments `DuelsWon` once. An accepted rematch increments `RematchesWon` once and does not reapply first-win progression. A non-rematch invokes `ModuleZRivalProgression.MarkRivalDefeated(result.RivalId)` and retains its unlock/completion behavior. The existing victory and unlock messages are preserved.

## 14. Defeat side effects

Defeat increments `DuelsLost` once and, for an accepted rematch, `RematchesLost` once. It applies no rival-defeat progression and preserves the existing normal/rematch defeat messages.

## 15. Draw → Defeat preservation

`Duel3DMatchResult.Draw` maps directly to `DuelOutcome.Defeat` once in the runtime boundary. The compatibility processor therefore applies the existing defeat flags, statistics, message, save, cleanup, and return delay. Duel visual/feedback presentation still receives the original Draw runtime result before contract mapping, preserving its current presentation behavior.

## 16. Abandon side effects

Abandon increments `DuelsAbandoned` once and, for an accepted rematch, `RematchesAbandoned` once. It applies no progression and preserves the normal/rematch abandon message and 0.8-second return delay.

## 17. Rematch authority

All migrated result policy reads `acceptedContext.IsRematch`. Normal result processing no longer reads `ModuleZDuelSessionState.IsRematch` or `ModuleZGameState.CurrentDuelIsRematch` as authority. The Legacy current-rematch field remains a compatibility projection and is reset after processing.

## 18. Result identity validation

`DuelResultBridge` requires `result.RivalId == acceptedContext.RivalId`. A mismatch logs an explicit rejection through `Duel3DResultManager`, applies no compatibility side effects, does not guess a rival, and leaves the operation unresolved.

## 19. Idempotency

The existing runtime-local `resultResolved` guard remains. It is set immediately before the accepted outcome switch applies side effects. Repeated completion or abandon calls cannot increment statistics, progression, saving, session cleanup, or navigation twice. No global idempotency state was added.

## 20. Save/session/navigation ordering

For each accepted outcome the preserved order is:

```text
idempotency guard
→ flags/statistics/progression/messages
→ CurrentDuelIsRematch reset
→ ModuleZSaveManager.SaveGame()
→ ModuleZDuelSessionState.Clear()
→ result log
→ schedule return (1.5s victory/defeat; 0.8s abandon)
→ ReturningFromDuel = true
→ IsPaused = false
→ ModuleZSceneController.LoadOpenWorld()
```

Achievement evaluation remains coupled to `SaveGame` and therefore occurs at the same lifecycle point.

## 21. Direct-scene fallback

S1.4-02 constructs one accepted fallback `DuelContext` in `DuelBootstrap` when no active session exists. The builder passes that exact context into the result manager. Direct-scene results therefore use the accepted fallback context and do not introduce a second result fallback.

## 22. Remaining Legacy compatibility

`DuelCompleted`, `DuelWasCancelled`, `DuelWasLost`, `DuelWasAbandoned`, statistics counters, `LastDuelResultMessage`, `PendingOpenWorldMessage`, `CurrentDuelIsRematch`, `ReturningFromDuel`, and the session clear operation remain. `ModuleZGameState` and `ModuleZDuelSessionState` removal is deferred. Return position remains on accepted context/Legacy compatibility state and is not part of `DuelResult`.

## 23. Static audit

Normal result authority is `accepted DuelContext + explicit DuelResult`. Runtime match completion and abandon each converge on `Duel3DResultManager.Complete`, `DuelResultBridge.Complete`, and one compatibility outcome switch. Result-manager rival/rematch reads from session/current Legacy authority are removed. Draw has one mapping to Defeat. Remaining Legacy writers are reset/load/entry compatibility or the single result compatibility processor and are classified in the pull request.
