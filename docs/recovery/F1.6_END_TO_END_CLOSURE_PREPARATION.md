## Independent Unity CI feasibility decision

Current `.github/workflows/modulez-static-validation.yml` runs on `windows-latest` for PRs targeting `develop` and manual dispatch. It parses PowerShell, checks fail-closed wrapper guards, runs STATIC-001–032, and uploads JSON/log artifacts. It has no `push` trigger for `develop` and never runs Unity. `ProjectSettings/ProjectVersion.txt` pins `6000.3.13f1` (`8c4f11e4fb20`). A read-only GitHub inventory at this baseline found **zero visible repository Actions secrets and zero registered self-hosted runners**; secret values were neither requested nor read. A GitHub-hosted Windows runner is available for the existing static job, but the repository has not demonstrated a licensed installation of this exact Unity editor on that runner.

Unity CI is **BLOCKED**, not simulated by static CI. A future safe job needs, in this order:

1. Project Owner-approved Unity license/activation method and secret scope, without exposing credentials to untrusted PR code. GitHub withholds Actions secrets from fork PRs; do not work around this using `pull_request_target` to execute fork code with secrets.
2. A trusted Windows runner provisioned with the exact editor revision, or a vetted installation step that verifies it before the wrapper runs. The wrapper currently assumes a Windows profile layout and accepts an explicit `-UnityPath`; neither editor availability nor license activation is established on CI.
3. A dry-run validation of the existing process-root guard, reparse/overlap checks, Unity replacement tracking, and post-exit real-profile fingerprint check on that runner. The job must fail closed if the root or profile cannot be resolved; no direct Unity invocation may bypass the wrapper.
4. A bounded mandatory subset (static, compile, EditMode, ordinary PlayMode, dedicated persistence and shutdown), separate XML/log artifacts, nonzero exit propagation, reasonable job timeouts and concurrency control. `smoke -EnableSmoke` remains a separate owner-authorized gate, not a default PR job.
5. Trigger policy for trusted PRs **and `push` to `develop`**, with documented handling of fork PRs lacking secrets. Publish artifacts even on failure without treating artifact publication as test success.

Do not add a workflow until these prerequisites are verified. [GameCI's current test-runner documentation](https://game.ci/docs/github/test-runner/) requires Unity activation credentials; [GitHub's secret documentation](https://docs.github.com/en/code-security/reference/secret-security/secret-types) states that Actions secrets are unavailable to fork PRs, and [GitHub's `pull_request_target` guidance](https://docs.github.com/en/actions/reference/security/securely-using-pull_request_target) warns against running untrusted PR code with privileged secrets. These are feasibility references, not evidence that this repository's Unity CI has passed.

## Reproducible controlled end-to-end procedure

**Procedure only; execution requires separate Project Owner authorization.** Use a fresh, disposable checkout of the approved commit, with no unrelated tracked changes. Before any Unity stage, confirm the exact `develop` SHA, project/editor revision, backup/persistence safety policy, no conflicting Unity validation process, and an ignored output directory outside `Assets`. Do not copy, restore, delete or overwrite real save/settings files. Do not use direct `Unity.exe` commands: the checked-in wrapper is the process-level isolation and external post-exit fingerprint boundary.

On the approved Windows host, run each stage independently and retain its exit status and artifacts:

```powershell
& .\Tools\Validation\Invoke-ModuleZValidation.ps1 static
& .\Tools\Validation\Invoke-ModuleZValidation.ps1 compile
& .\Tools\Validation\Invoke-ModuleZValidation.ps1 editmode
& .\Tools\Validation\Invoke-ModuleZValidation.ps1 playmode
& .\Tools\Validation\Invoke-ModuleZValidation.ps1 persistence
& .\Tools\Validation\Invoke-ModuleZValidation.ps1 shutdown
```

Stop on any nonzero exit, absent XML/log, zero discovered ModuleZ tests, failed/skipped ModuleZ case, profile fingerprint mismatch, unexpected Unity error, or unexplained warning. The wrapper captures save/settings existence, size, UTC write time and SHA-256 before each Unity launch, then compares both **after process exit**; retain the PASS line or failure evidence for each run. `shutdown` separately requires a nonempty isolated exit-time save. `editmode`, `playmode`, `persistence` and `shutdown` produce distinct `*-results.xml` and `*.log` under ignored `artifacts/validation/`; `compile` produces its own log and `static` produces JSON/log. Validate exact assembly/case counts from XML, not only aggregate Unity totals. Review `git status --short` afterward for unexpected tracked changes. The `tests` and `all` aliases can be run as additional confirmation but duplicate work; neither includes shutdown or smoke.

`smoke -EnableSmoke` is **not part of the above authorization**. If separately approved later, run it only through the dedicated guarded stage, inspect its separate XML/log and external post-exit guard, and stop rather than automatically retrying a failure. Manual L4 acceptance remains the versioned LIFE checklist in the F1.5 closure record; it is not replaced by automated static or scene checks.
