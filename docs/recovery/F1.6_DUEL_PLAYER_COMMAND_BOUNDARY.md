# F1.6 Duel Player Command Boundary

## Scope and baseline

S1.6-05A starts from `develop` at `8acb3276fbbe6cff174df08a7982cee79a0e6a0b`. It adds one public production operation for the current Duel3D player placement and PlayMode regression coverage. No scene, package, ProjectSettings, input-system, AI API, or production assembly change is included.

## Existing action and decision

Before this slice, `Duel3DRuntimeBuilder.HandlePlayerInput()` sent Legacy Space to the private `TryPlacePlayerPiece()`. That method already contained the full accepted placement path: calculate Z-piece cells, reject last-piece contact or invalid placement, call `Duel3DPiecePlacement.PlacePiece`, record the last cells, create visuals, play feedback, resolve groups, update HUD, transfer the turn, and schedule `PlayOpponentTurn()` using the rival reaction delay.

The same implementation is now `public bool TryCommitCurrentPlayerPiece()`. Space calls it directly. There is no parallel private placement method. The boundary expresses a production player command that a later input adapter or UI controller can call; it does not expose board mutation or AI control.

## Command contract

The command returns `false` without gameplay-state mutation if the build has not completed, the component is inactive, required board/resolver/configuration/runtime roots are unavailable, the player does not own the turn, the match is finished, removal is resolving, the game is paused, the last-piece restriction rejects the cells, or canonical placement rejects them. The existing invalid-placement feedback remains for the two placement-rule rejections.

It returns `true` only after `PlacePiece` accepts the player piece. If that accepted move finishes the match, `true` still reports the accepted move. Otherwise the original visual, resolution, feedback, HUD, turn-transfer, and delayed private AI pipeline is preserved.

The present Legacy Input adapter calls `TryCommitCurrentPlayerPiece()` on Space. A future Input System adapter or UI/controller should call that same command. `PlayOpponentTurn()` and `TryPlaceOpponentAIPiece()` remain private and unchanged.

## Persistence isolation

The new Duel command fixture fingerprints the real `modulez_save.json` and `module_z_settings.json` before each test, sets `ModuleZPersistencePaths.SetRootOverride()` to a unique OS-temporary directory before loading Duel, and clears the override during guaranteed teardown after scene destruction. It restores Unity random state and time scale, removes only its validated temporary directory, and compares both real-profile fingerprints afterward. External before/after checks for the validation profiles also found both real files unchanged. No backup/restore of user data was used.

## Architectural observations and remaining risk

The command reuses the existing production placement and private AI path; the change adds no mutable global state, public board setter, public AI command, test mode, or additional Legacy Input consumer. CMD-008 is a source-level delegation check, while gameplay acceptance and AI response are runtime checks. This slice does not automate the normal OpenWorld-to-Duel transition or the full result/return smoke; those remain S1.6-05 work. The AI's choice remains game-random in production; the test pins Unity random input for reproducible coverage on the fixed Unity version.

REC-007 remains in progress. REC-008 remains partially migrated/stabilized.
