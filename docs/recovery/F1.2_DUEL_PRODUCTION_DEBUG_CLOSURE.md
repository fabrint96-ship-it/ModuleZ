# F1.2 — Duel Production/Debug Closure

Slice: `S1.2-03`

Status: F1.2 closed; transitional Duel state boundary deferred to F1.4

## Problem before recovery

The enabled production `Duel.unity` scene serialized `Duel3DDebugBootstrap`. That adapter could inject a Madrid debug rival, reset result flags, remove legacy scene objects by name, and create `Duel3D_Runtime`. Production startup therefore passed through debug behavior and had no explicit scene-scoped production owner.

## Recovery sequence

### S1.2-01 — Production boundary

Introduced scene-scoped `DuelSceneRoot` lifecycle ownership and `DuelBootstrap` production composition. The preserved `Duel3DRuntimeBuilder` remained the gameplay runtime implementation. The transitional scene adapter delegated debug to production; production never depended on debug.

### S1.2-02 — Scene composition migration

Migrated `Duel.unity` to serialize one `DuelSceneRoot` GameObject with:

- `DuelSceneRoot`, GUID `5afc01e7285c48288b0d760699b04b45`;
- `DuelBootstrap`, GUID `b364f59672e2480c89e52673b00289fa`;
- an explicit serialized root-to-bootstrap reference.

The `Duel3D_DebugBootstrap` GameObject and debug script GUID were removed from production composition.

### S1.2-03 — Zero-reference audit and cleanup

The complete repository was searched for:

- `Duel3DDebugBootstrap`;
- `Duel3D_DebugBootstrap`;
- deleted GUID `7b34cdc96a938584e816e44d085e3a90`;
- `DuelSceneRoot`, `DuelBootstrap`, `Duel3DRuntimeBuilder`, and `Duel3D_Runtime`.

Runtime/serialized/configuration searches covered `Assets`, `ProjectSettings`, and `Packages`, including C# source, scenes, prefabs, assets, and build configuration. Documentation was classified separately from runtime dependencies.
