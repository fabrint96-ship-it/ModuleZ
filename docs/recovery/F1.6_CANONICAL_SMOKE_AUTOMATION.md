# F1.6 canonical gameplay smoke — guarded integration

## Scope and baseline

S1.6-05B adds one production-path PlayMode smoke fixture on `develop` baseline
`e822215c79df44287fd7e09459e52d0dcbc88d61`. It does not change gameplay,
production scenes, persistence implementation, packages, or project settings.
The integrated S1.6-05Q exit-time persistence protection remains the storage
safety boundary.

## Deliberate invocation

The fixture belongs only to the `Smoke` category. It has no unconditional
`[Ignore]` attribute because that would require editing source to run it.
Instead, its setup calls `Assert.Ignore` before any scene is loaded unless
`MODULEZ_CANONICAL_SMOKE_OPT_IN=1` is present. The checked-in wrapper sets that
marker only for an explicit invocation:

```powershell
& .\Tools\Validation\Invoke-ModuleZValidation.ps1 smoke -EnableSmoke
```

Invoking `smoke` without `-EnableSmoke` fails before Unity starts. Passing
`-EnableSmoke` with any other stage also fails. The wrapper restores the prior
process environment marker in `finally`. `playmode`, `tests`, and `all` exclude
both `Smoke` and `Shutdown`; `persistence` selects only `Persistence`, and
`shutdown` selects only `Shutdown`. Direct Editor Test Runner selection without
the opt-in marker is skipped before gameplay setup. The marker is a deliberate
execution gate, not a security credential; manual environment manipulation is
outside the wrapper contract.

## Production path covered

The only direct scene load is the initial Boot test entry. The fixture then
invokes the MainMenu New Game button's production listener, waits for OpenWorld
SceneRoot R3 readiness, calls Madrid `DuelStarterInteractable.Interact()`, and
observes the `DuelContext`/active-session handoff and Duel SceneRoot R3 readiness.
It invokes the public `Duel3DRuntimeBuilder.TryCommitCurrentPlayerPiece()`
command, observes player board/visual changes and a later opponent placement
from the normal private AI scheduling path, then calls the public
`Duel3DResultManager.AbandonDuel()`. It verifies result flags, session cleanup,
an isolated save, OpenWorld return and readiness, return position/message
consumption, and production `ModuleZSceneController.ReturnToMainMenu()`.
The normal transition must not emit the direct-scene fallback warning.

State-driven waits are bounded: scene/readiness navigation by the shared
20-second driver, AI response by 15 seconds, and menu readiness by 20 seconds.
Unexpected gameplay warnings/errors/exceptions are collected and fail the test.
The fixture uses only public production methods/properties through the existing
test-only `RuntimeContractProbe`; it does not call private AI/gameplay methods.

## Persistence and cleanup

The wrapper establishes a unique process-level root under ignored
`artifacts/validation/process-data/` before Unity starts. It rejects overlap
with the real profile and reparse-point ancestors, tracks Unity process exit,
and compares real save/settings fingerprints after exit regardless of XML
status. Production batchmode path resolution fails closed without an isolated
root. The fixture additionally requires that process root before Boot, creates
a unique per-test child beneath it, and sets `ModuleZPersistencePaths`'s
explicit override. Teardown destroys its scene-owned and Boot DDOL objects,
clears session state, restores time/random state, and deletes its per-test data.
If an autosaver remains alive, teardown retains the override rather than
redirecting a later quit save to the real profile. The process-level root
continues to protect exit-time callbacks after teardown.

Smoke results are generated at `artifacts/validation/smoke-results.xml` and
`artifacts/validation/smoke.log`; both are ignored. Missing XML, zero tests,
skipped tests, failed tests, nonzero Unity exit, or a changed real profile
causes the wrapper to fail.

## Validation evidence and limits

The first controlled S1.6-05B run on 2026-10-13, before this wrapper opt-in
change, ran exactly once with the fixture temporarily unignored. Its Unity
process exited 0; XML reported one passed test, zero failed/skipped. The
post-exit real-profile guard passed for both save and settings. The Unity log
showed OpenWorld/Duel readiness, a player placement, a real AI placement,
abandon, isolated save writes, OpenWorld return, and MainMenu return. The
fixture was re-disabled immediately after that run. The new opt-in gate has
not been used to rerun gameplay as part of this integration preparation.

The smoke does not synthesize Legacy movement/input or test interaction
proximity, pause UI, victory, defeat, rematch, a second roundtrip, visual/audio
fidelity, or full save-schema semantics. It proves one controlled abandon
roundtrip. Engine-level licensing and shutdown diagnostics from the prior
batchmode log are distinct from gameplay-log assertions; a future occurrence
must still be reviewed rather than silently called an application PASS.

REC-007 remains in progress: this is one guarded automated layer, not the
consolidated regression-suite or CI closure.
